3 Preguntas

3.1 Sobre el Ejercicio 1 (Vectorización):

Intenta explicar qué sucedería si decides hacer este ejercicio en Python y creas caudales_m3s como una Lista nativa ([1500, 2100…]) y la multiplicas directamente por 1000 (caudales_m3s * 1000). ¿Realizaría la operación matemática deseada? ¿Qué librería de Python soluciona este problema y cómo se diferencia este comportamiento del de R o Julia?

  • No, no realizaría la operación matemática deseada. Si multiplicas una lista nativa de Python por un entero (por ejemplo, [1, 2, 3] * 1000), Python interpreta el operador * como una operación de replicación o repetición.El resultado sería una lista gigantesca que contiene los mismos 5 valores originales repetidos 1000 veces uno tras otro. En lugar de transformar el caudal de la estación Honda de \(1500\) a \(1,500,000\), tendrías una lista con \(5000\) elementos donde el número \(1500\) aparece mil veces.La solución: NumPyLa librería que soluciona este problema en Python es NumPy mediante su estructura principal: el np.array.NumPy introduce el concepto de Broadcasting (difusión). Al convertir la lista en un arreglo de NumPy, la librería redefine el comportamiento de los operadores aritméticos. Cuando NumPy ve array * 1000, entiende que debe “difundir” el escalar (\(1000\)) sobre cada elemento individual del vector, ejecutando la operación matemática elemento a elemento a nivel de lenguaje C (lo cual es extremadamente rápido).

Diferencia con R o Julia

A diferencia de Python, R y Julia fueron diseñados desde su origen para el cálculo numérico y estadístico, por lo que su comportamiento nativo es diferente: - En R La estructura básica es el vector. R no tiene “escalares” puros; el número 1000 es en realidad un vector de longitud 1. Por lo tanto, el lenguaje aplica de forma nativa el “Reciclaje de Vectores”, realizando la multiplicación elemento a elemento sin necesidad de librerías externas. - En Julia El lenguaje está diseñado para el alto rendimiento científico. Aunque permite operaciones vectorizadas directas, es famoso por su sintaxis de “Dot Operators” (operadores de punto). En Julia, usarías caudales_m3s .* 1000. Ese punto indica explícitamente que la operación debe aplicarse a cada elemento, combinando la facilidad de lectura con una velocidad idéntica al lenguaje C o Fortran.

En resumen: Mientras que en Python se depende de NumPy para “activar” el comportamiento matemático de los vectores, en R y Julia ese comportamiento es el estándar del lenguaje.

3.2 Pregunta General (Indexación):

Escribe la línea de código exacta que usarías en tu lenguaje elegido para extraer las tres primeras estaciones del DataFrame del Ejercicio 2 usando indexación por rangos (slicing). Explica brevemente si el límite superior del rango que escribiste se incluye o se excluye en el resultado final, justificando esto según el tipo de indexación (Base-0 vs Base-1) de tu lenguaje.

primeras_tres = df_aire.iloc[0:3]

  • Base-0: Python utiliza una indexación basada en cero, lo que significa que el primer elemento está en la posición 0.

  • Límite superior: En el slicing nativo de Python y en .iloc, el límite superior se excluye.

  • Justificación: Al escribir 0:3, Python toma los índices 0, 1 y 2. Esto es una convención de diseño que permite saber rápidamente cuántos elementos se están extrayendo restando los índices (\(3 - 0 = 3\)), facilitando el manejo de subconjuntos de datos en la memoria.

primeras_tres <- df_aire[1:3, ]

  • Base-1: R es un lenguaje de indexación basada en uno, por lo que la primera fila se encuentra estrictamente en la posición 1.

  • Límite superior: En R, el límite superior se incluye.

  • Justificación: El operador : en R genera una secuencia completa. Al escribir 1:3, R genera el conjunto \(\{1, 2, 3\}\). Al ser un lenguaje diseñado por y para estadísticos, se prioriza que el rango escrito coincida exactamente con la selección física de los elementos, evitando la necesidad de “sumar uno” mentalmente para alcanzar el último registro deseado.
